## Issues / Deviations
- Context7 MCP tools were not present in my available tool set this session (instructed to use them for library docs) — substituted npm-registry inspection + the `fastify-multipart` README fetched via WebFetch for the dependency-compatibility research; flagged to team-lead in the plan message, accepted.
- `product-photos.ts` is 294 lines (over the 200-line soft guideline) — deliberate: the phase file's "Related Code Files" list is exclusive, and `publishProductPhoto` fits this file's existing Prisma+storage+coordinator composition better than any of the other 5 listed files; inventing an unlisted 7th file seemed like the worse trade-off. Flagging for team-lead/reviewer judgment.
- HEIC support is very likely to evaluate `false` on virtually every real deployment using the default `npm install sharp` prebuilt binary (confirmed empirically on this host: `sharp.format.heif.input.buffer` is `true`, but decoding a real HEVC-coded HEIC fails with "Support for this compression format has not been built in" — the static flag alone would have been a false positive, which is exactly why the phase spec requires a real decode probe, not just the flag). This is expected/correct behavior per spec ("HEIC only when startup decode capability passes"), not a defect — but worth Ops awareness: HEIC uploads will likely be rejected in production unless a custom-built sharp/libheif/libde265 is deployed.
- `withMediaMutationLease` is a visibility/fencing primitive (Redis lease per invocation, tracked in an active-leases set), not a per-resource mutex — resource-level serialization for photo positions is the separate per-product `FOR UPDATE` lock. Documented inline; flagging here in case Phase 7's freeze-policy design assumed otherwise.
- `MEDIA_PUBLIC_BASE_URL` is used today only by the serializer's public-URL branch; no product is `active` with a published photo yet in this phase's own tests (Phase 4 owns publication's DB-write side), so that branch is exercised structurally (unit-level in `product-media-storage.test.ts`'s URL-derivation tests) but not through a full moderation-approval integration path — that's Phase 4's to add.
